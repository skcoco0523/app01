# 汎用ゲームデータ・アセット仕様書 (GAME_DATA_SPEC.md)

## 1. 概要
本ドキュメントは、管理画面（`AdminGameController.php`）からパブリッシュ（自動生成）され、フロントエンド（Phaser等）のゲームエンジンが動的に読み込む、各ゲーム要素のデータ構造およびアセット配置規約を定義します。

特に、AI生成画像をグリッドシステムに適合させ、ステージ管理で利用するためのワークフローを重視しています。

---

## 2. ファイル配置とデータ種別ごとの出力ルール

### ① アトラスシート・マニフェスト (`atlas_sheets.json`)
画像ファイル名単位のデータ構造です。キャラクターのモーションや、ステージのグリッドパーツで使用されている画像ファイル名を走査し、DB（`GameSpriteSheet`）に登録されているアトラス定義データ（`pixel_data`）を収集・結合したマニフェストファイルです。
* **配置パス**: `public/games/{game_key}/atlas_sheets.json`

### ② データ種別ごとの出力マトリクス

| データ種別 | 一覧ファイルパス | 個別詳細ファイルパス | 特記事項 |
| :--- | :--- | :--- | :--- |
| **character** | `.../characters.json` | `.../characters/{character_key}.json` | モーションデータを含む詳細出力 |
| **stage** | `.../stages.json` | `.../stages/{number}.json` | マップ・レイヤー・エンティティ構造 |
| **item** | `.../items.json` | *(出力なし)* | **GameItem**（グリッドパーツ）の一覧 |

---

## 3. グリッドシステムとAI生成アセットの規約

システムは **1グリッド = 32px** を基本単位として設計されています。AI生成画像を利用する場合、以下のステップで規格化を行います。

### 3.1 AI画像生成時の注意点
*   **アスペクト比の指定**: Gemini等に対し、`1:1`, `1:2`, `2:1` などの具体的な比率を指定して生成します。
*   **高解像度の許容**: 生成される画像のピクセル数は任意（高解像度可）です。後の定義フェーズで縮小適合させます。
*   **密度の統一**: 複数のパーツを並べた際に違和感がないよう、描き込みの密度やスタイルを統一します。

### 3.2 アトラス定義（切り出し）ワークフロー
管理画面の「アトラス切出」において、AI画像をシステム規格に適合させます。
1.  **グリッド枠の指定**: パーツを何グリッド分として扱うか（`grid_w`, `grid_h`）を決定。
2.  **エリア定義**: マウス操作により、指定したアスペクト比を維持したまま、画像上の最適な範囲を移動・拡大・縮小して選択。
3.  **規格化**: 選択された範囲が、ステージ配置時に自動的に `grid_w * 32px` / `grid_h * 32px` に縮小・適合されます。

## 4. データ構造詳細（JSONスキーマ）

### 4.1 ステージ詳細データ (`stages/{number}.json`)
ステージは「固定レイヤー」と「グリッドエンティティ」の混合構造です。
```json
{
  "base": {
    "width": 2000,
    "height": 600,
    "groundY": 500
  },
  "layers": [
    {
      "key": "bg_cloud",
      "atlas": "background.png",
      "x": 100, "y": 50, "w": 400, "depth": 1,
      "scrollFactorX": 0.5
    }
  ],
  "entities": [
    {
      "type": "item",
      "item_id": 10,
      "key": "stone_pillar",
      "atlas": "monuments.png",
      "frame": "pillar_01",
      "x": 320, "y": 436,
      "grid_w": 1, "grid_h": 2,
      "depth": 10
    }
  ]
}
```

### 4.2 アイテム（グリッドパーツ）データ (`items.json`)
パーツレコード単位のデータ構造です。`GameItem` モデルから出力される、定義済みパーツのマスターデータです。
* **grid_w / grid_h**: そのパーツが占有するグリッド数。
* **atlas_frame**: 対応するアトラス内のフレーム名。

---

## 5. 運用上の懸念点と対策
*   **解像度ギャップ**: 極端な縮小によるボケ防止のため、AI生成時はディテールを詰め込みすぎない。
*   **アンカー（接地）**: アトラス定義時、枠の底辺をパーツの接地部分に厳密に合わせる。
*   **当たり判定**: 現状は `grid_w/h` に基づく矩形判定が基本。形状が複雑な場合は、画像内の余白を最小化する。
