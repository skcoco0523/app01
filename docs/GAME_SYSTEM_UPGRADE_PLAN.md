# ゲームシステム拡張計画書 (GAME_SYSTEM_UPGRADE_PLAN.md)

## 1. 概要
本ドキュメントは、現在の固定キャラクター表示から、`view_mode` に応じた基盤の切り替え、およびユーザー情報に基づいたキャラクター選択・制御を実現するための拡張計画を定義します。


## 2. view_mode による挙動の分離
ゲームの種類（`view_mode`）に応じて、読み込むシーンや物理エンジンの設定、キャラクターの操作方法を動的に切り替えます。

### 2.1 定義されている view_mode (想定)
| view_mode | 特徴 | 物理設定 |
| :--- | :--- | :--- |
| **platformer** | 横スクロール型（現在のデフォルト） | 重力あり、衝突判定あり |
| **topdown** | 見下ろし型アクション | 重力なし、全方向移動 |
| **side_view** | 格闘・対戦型 | 固定画面、左右移動中心 |

### 2.2 シーン構成の動的変更
`main.js` において、`window.GAME_CONFIG.viewMode` を参照し、対応する `GameScene` クラス（またはそのサブクラス）をロードする仕組みを導入します。

## 3. キャラクター選択とユーザー制御
ユーザー情報（ログイン状態、権限、所持データ）に基づき、使用可能なキャラクターを動的に制御します。

### 3.1 制御フロー
1. **DataLoaderScene**: 共通データ（`atlas` / `characters`）をロード。
2. **CharacterSelectScene (新規)**: 
   - `characters.json` から `type: player` の一覧を取得。
   - `login_user_flag` や `admin_only_flag` を現在のユーザー権限と照合。
   - 使用可能なキャラクターのみ選択を許可（不可なものはグレーアウトまたは非表示）。
3. **GameScene**: 選択された `character_key` を基にプレイヤーを生成。

### 3.2 ユーザー権限の受け渡し
`play.blade.php` から `window.GAME_CONFIG` に、現在のユーザーの権限情報を安全な形で付与します。

## 4. ステージ構築システムの基盤（グリッド ＆ AIワークフロー）
将来の `view_mode` 拡張を支える共通基盤として、以下の仕組みを確立・維持します。

### 4.1 共通グリッド基盤
*   **32pxグリッド**: `platformer` や `topdown` における標準的な配置・衝突判定の単位。
*   **GameItem エンティティ**: すべての `view_mode` で共通して利用可能な、規格化された配置オブジェクト。

### 4.2 AI生成アセット適合ワークフローの標準化
不規則なAI画像をシステム規格（16px/32px）に強制適合させるワークフローを、今後のアセット追加の標準手順とします。

## 5. 実装ステップ（フェーズ）

### フェーズ1: ステージ構築基盤の確立（現在完了）
- グリッドベースのステージエディタの実装。
- AI生成画像をグリッドに適合させるアトラス定義UIの構築。

### フェーズ2: キャラクター選択シーンの導入
- `CharacterSelectScene.js` の作成。
- ユーザー権限に応じた表示制御の実装。

### フェーズ3: view_mode 対応の深化
- `GameScene.js` を基底クラス化し、各視点に応じた物理挙動を分離。
- 各 `view_mode` でのグリッドパーツ（GameItem）の挙動定義。

## 6. 成功基準
- ゲーム開始前にキャラクター選択画面が表示されること。
- 管理画面で定義されたグリッドパーツが、各 `view_mode` で正しく配置・表示されること。
- `view_mode` を変更した際、適切な操作系と物理挙動が適用されること。




# AI生成アセット・グリッド適合規約（ステージ配置用）
1. **画像作成**: ステージ配置用パーツの画像作成時は「ピクセル数」ではなく「アスペクト比（1:1, 1:2等）」を重視する。
2. **規格化**: 高解像度画像であっても、アトラス定義画面で「グリッド枠（32px単位）」にマウスで拡大・縮小して適合させる。
3. **ステージ配置**: 配置時は32px単位のグリッドにスナップし、定義したグリッドサイズ（grid_w/h）に自動縮小される前提で設計する。
*注: キャラクター等の組み合わせアセットはグリッドに縛られず、ピクセル単位の自由な調整を優先する。*
